# 週次更新の手順（毎週1回）

目的：日本の経済・政治について、読む人が「自分の国のことに詳しくなり、関心を持ち、正しく批評できる」ようにする。内容の正確さを最優先にし、充実度を少しずつ高める。

## 1. 変化を集める（直近1週間）
次の一次資料を優先して確認する。
- 内閣府 経済財政諮問会議（会議結果・資料・議事要旨）
- 内閣官房 日本成長戦略会議・日本成長戦略本部
- 財務省（予算・国債・概算要求）、日本銀行（金融政策決定会合）
- 総務省統計局（消費者物価）、内閣府（GDP・経済見通し）
- 首相官邸（閣議決定）
- 主要な世論調査（共同通信、JNN、NHK、時事、日経など。調査主体・調査日・設問を確認）

## 2. 直す・足すものを決める
- 古くなった数字（長期金利、物価、世論、予算の進み具合、日程の「いま」の位置）
- 新しく決まったこと（予算案、実行計画、税制改正、防災庁の発足など）
- 読む人の関心が高そうな論点（報道や世論から推測し、理由を記録する）
- 1回の更新で追加する新しい章・ブロックは最大1つ。既存の内容の正確さを先に保つ

## 3. ファクトチェック（必須）
- 載せる・変える主張ごとに台帳をつくり、サブエージェントに一次資料で検証させる
- 判定が「誤り」「未確認」のものは載せない。「要注意」は表現を条件付きにする
- 意見・評価は、誰の意見かを必ず書く。サイト自身の整理は「当サイトの整理」と明記する
- 特定の政党や政治家を持ち上げる・おとしめる書き方をしない

## 4. 反映する
- `index.html` を直接編集する（デザインの約束：色はCSSトークン、明暗両テーマ、スマホ幅で横にはみ出さない、動きを減らす設定に対応）
- ページ下部の「更新履歴」に1行追加し、最終更新日（`#lastmod`）、JSON-LDの `dateModified`、`sitemap.xml` の `lastmod` を更新する
- パソコンとスマホ幅で表示を確認し、コンソールエラーがないことを確かめる

## 5. 公開と報告
- コミットしてプッシュする（GitHub Pages が自動で反映）
- 変更点、ファクトチェック結果（件数と判定）、次回の候補を報告する
